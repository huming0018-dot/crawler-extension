# v4 Mac 自动更新

## 4.2.5 权限通道

4.2.5 接通包安装的助手固定读取同仓库 `channel-kol.json`，用于已经明确授权小红书与 B 站域名的新版本。旧 `channel.json` 保持 4.2.3，避免向旧权限安装反复推送必然被拒绝的包。4.2.4 及更早助手需要一次接通包迁移；之后同权限、同插件公钥的新版本可继续签名 OTA。权限扩大仍拒绝自动更新；签名、文件摘要、握手、回滚和原身份保护不变。助手自身仍不通过扩展包更新。

4.2.3恢复独立于扩展 worker 的系统定时 OTA。macOS14+，通用 arm64/x86_64 程序；本轮硬件为 Apple 芯片，Intel 仅完成编译。用户保留原浏览器、个人资料、参与身份和插件目录。

## 运行方式

安装时注册两个 LaunchAgent：`.ota` 在登录时及每小时执行 `--poll`，`.recovery` 每5分钟执行 `--recover`。系统轮询不需要浏览器正在运行。

- 浏览器运行时，系统任务下载并验证签名包、文件摘要和权限形状，保存缓存，不替换正在使用的目录。扩展等待状态落盘，再通过本机助手原子切换并只 reload 自己；可从已验证缓存离线完成更新。
- 浏览器关闭时，已有4.2.3或更新版可直接原子更新文件，保留旧目录，并标记等待首次启动。没有启动浏览器不会触发5分钟超时回退。首次加载后确认版本和发布摘要；确认失败或入口代码损坏仍走回退。
- 对4.2.2及以前客户端，系统任务只准备缓存，避免旧客户端无法处理离线切换的握手。升级到4.2.3后才启用关闭浏览器期间的目录切换。
- 插件内关闭自动更新会同步关闭系统轮询。新装助手默认不轮询，首次新版客户端握手时同步原有开关。保存开关失败会报错，不伪装成功。
- 系统任务和浏览器共用排他锁。竞争时客户端一分钟后重试，避免每小时在同一时刻反复撞锁。不会退出、强杀或重启用户浏览器。

## 现有安装衔接

4.2.3扩展本体可通过原有签名通道更新。**独立系统 OTA 还需要协议2更新助手和新 LaunchAgent。**旧4.2.0助手只有固定status/apply/ack/rollback能力，没有升级自身或安装新系统任务的接口；发布扩展 ZIP 不能把它自动变成协议2助手。

因此旧助手需要一次4.2.3接通包升级。包自动定位原目录、更新助手及系统任务，不重新报名、不清空身份；当前4.2.0客户端还需在扩展页刷新一次。具体固定提交下载及校验命令由 crowd-pages 的4.2.3 bootstrap说明提供。此限制必须明说，不能把新代码发布当成原设备已经接通。

## 验证与边界

`python3 v4/updater/test_host.py`：真实编译宿主，签名/摘要、原子替换、握手、回退、防重放、权限扩张拒绝、路径穿越和中断清理。

`python3 v4/updater/test_system_ota.py`：实际macOS launchd启动隔离测试任务；禁用不联网、运行中缓存、离线使用缓存、关闭期间切换、延迟握手、缓存篡改拒绝。浏览器进程存在与否在此测试中使用显式fixture值，避免影响用户现有Chrome。结束后注销测试LaunchAgent。

设置 `CROWD_SYSTEM_OTA=1` 后运行 `v4/tests/update-engine.cjs`：真实Chrome、原有发布包升级候选包、坏代码回退；主动关闭测试浏览器后系统更新，再打开同一测试资料确认新版本和原身份/队列保留。所有测试使用独立目录与假身份，不操作真实参与者资料。

生产助手公钥固定，私钥只在发布机，不进仓库或ZIP。只接受固定动作和固定GitHub发布通道，不执行远程脚本。协议2新增`settings`动作，仅接受自动更新布尔开关。缓存应用时重新验签/验哈希，不信任缓存文件名。权限、插件公钥或manifest其他结构变更仍拒绝自动更新。

助手自身的版本升级仍通过接通包完成。原设备加载版本、系统助手是否更新、真实采集回执必须分别验收；本机隔离测试通过不等于原设备已经升级。
