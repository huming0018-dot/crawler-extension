# 项目级取舍：保留有界适配，退出旧运行框架

## 目标与判断
用户允许项目重来，只保留值得保留的完整核心，同时暂停众包开发。不能据此把“测试不足”或“被调用”当作删除/保留的唯一标准。本批不修旧产品，不搭第二套框架。

比较三条路径：
1. 整套保留：保留任务领取、Chrome 生命周期、上传队列、配额/节律、参与者评分等现成路径，但仍要求维护紧耦合的浏览器/服务端/任务合同，且没有完整交付证据。大部分不是独立共享资产。
2. 全部删除：最省维护，却会误丢已实测有用、可独立输入输出的站点卡片适配。
3. 保留最小卡片适配，退出运行框架：选择本路径。卡片的价值是保留历史站点选择器、字段位置、同卡片来源关联与缺失语义，不是创造 DOM 解析器。平台通用 DOM 能力由调用方提供，不另建包或仓。

## 留下的完整边界
`extractNoteCards(document)` 的完整合同：输入拥有 querySelectorAll 的 DOM/同接口对象；逐卡片用 querySelector 取链接、标题、作者；返回可序列化记录数组。没有网络、全局 Chrome、全局 document、任务、文件或数据库依赖。

原 NOTE_CARD_SELECTOR、NOTE_LINK_SELECTOR、NOTE_ID_RE、_text、_cleanAuthor、extractNoteCards 函数体原样保留；只将 document 参数显式化、去掉浏览器 IIFE、增加 CommonJS 导出。不是拿一段无法调用的代码当核心，也不声称它仍提供关键词校验或详情页采集。

7 项 Node 离线用例通过：卡片隔离、空卡/空列表、无链接缺失标记、同卡标题回退、原作者时间清理、坏路径缺失标记、域名不认证的明确边界。作者清理和链接假设仍有局限；保留是窄合同价值判断，不是质量无缺陷认证。

## 退出范围与理由
- background、safety_engine、device_profile、sampler：任务/队列/浏览器调度强耦合。稳定信封 ID、失败退避、死信及权威进度等机制值得记录，但不需要为这些通用机制维护旧整套框架。不是因为缺测试就判定所有函数失效。
- 原 content listener 和详情提取：浏览器消息适配随框架退出；列表能力已保留。详情 cards-first 和 200 字截断不符合全文目标，不另修新提取器。
- onboarding/popup 的 HTML 和 JS、config：注册和显式加入/停止的局部流程已验证有用，但离开旧 Chrome/RPC/任务运行链无独立用途。留合同经验，不复制成另一套注册服务。
- manifest：退出安装入口，明确仓库不再能作为旧扩展加载。图标本批不删除，避免把未下载/未核内容顺带清除。

## 必须保留的经验和反例
- 新信封应在外部操作前持久化身份，未知结果重试复用原身份；不能仅用 last_sid 宣称全序列幂等。旧 A/B/A 回执本地累计会提前 done，权威服务端进度可纠正。
- 独立卡片字段不能跨卡片补齐；任务与页面关键词应匹配。保留模块只负责卡片字段，不包含后一个门槛。
- 安装不等于加入；停止采集与是否排空已存在队列必须分别定义。旧 UI 的“运行中”不等于实际运行状态。
- 服务端接收、浏览器正常路径、持续吞吐、跨重启可靠性是不同验收层次，不能用语法通过替代。

## 基线和影响
网页归并已合并。本候选直接基于已核对的远端 main `d3e99fa62e37b53cb61e83e900b19658b5af07e2`，不再依赖未合并补丁；保留整理前恢复点 `f4d1a49d5ed968c229035cab0d15d1273b1fd35b`。只有本批运行框架退出仍是本地候选，尚未写入远端。

删除 src 和 manifest 后，本仓不再能作为 Chrome/Firefox 扩展加载，也不能替换现有扩展安装目录或打成旧 ID 的 OTA 包。已有机器仍运行原安装物；本批没有停用它们。若未来需要线上退役，必须另行处理发布和设备，不以源码删除冒充完成。

crowd-pages、CRX/ZIP、updates.xml、公共存储、RPC、真实数据、设备配置均不改。Git 历史保留旧实现，不新建历史副本目录。LICENSE、历史协议和沿革保留但不代表当前功能。
